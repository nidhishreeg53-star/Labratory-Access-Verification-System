How the trees are used

Binary search tree of researchers (key = ID). Authentication searches it in O(log n) on average, adding inserts a node, and removing deletes a node (leaf, one child, or two children with the in-order successor). An in-order walk lists researchers sorted by ID.

General tree of zones. Facility → wings → laboratories, stored with first-child and next-sibling links. A researcher authorized for a wing may enter every laboratory below it, so authorization asks whether the requested lab lies in the subtree of the authorized node (depth-first search).

Binary search tree of the access log (key = request number). A reverse in-order walk lists the newest decision first. Its keys only increase, so it grows into a one-sided chain with height equal to its size (the live size and height are shown below); a self-balancing tree such as an AVL tree would fix that.

Order of checks: authentication, authorization, permission, revocation, lockdown. The first failure denies access, and the remaining checks are skipped.
